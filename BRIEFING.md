# Daily Threat Brief

Plain-English reporting for everyday readers: what happened, who is affected,
confirmed practical consequences, and what could happen next. Speculation must be
labeled and supported; no exploit recipes or sensational claims. Sources accompany
every item. The incident popup remains the place for technical details.

- Overview: 8 a.m. and 5 p.m. America/New_York, including daylight saving changes.
- Evening overview contains fresh developments, not a rewrite of the morning.
- Energy & Power, Water, Food & Agriculture, Finance, Healthcare, Internet &
  Telecom, Supply Chain: one daily roundup at 5 p.m., covering the preceding day.
- An opening brief seeds the panel on its first manual run.
- Date selector retains 30 days. Previous sector editions remain clearly dated.
- Publication targets can be delayed by GitHub scheduling and source/API latency.

`Publish Daily Threat Brief` refreshes the eight news feeds and reads current
articles independently of the map eligibility/geocoding pipeline. It uses the
same `OPENAI_API_KEY` secret and `OPENAI_MODEL` variable. It does not require a
new key, browser-side API access, or an API call per website visitor.

One summary request per edition, up to 100 reports and 5,000 characters per report;
14,000 maximum completion tokens. SDK retries are limited to one. Token usage is
recorded in workflow logs and each edition's `usage` field, so actual usage can be
reviewed before changing model or limits. No fixed dollar estimate is assumed.
Feed failures, excerpt-only evidence and review-limit omissions are disclosed.

Same-source fingerprints prevent unchanged reports reappearing in the overview.
The previous six overviews provide semantic context to avoid repeating the same
incident from another publisher; genuinely new impact/recovery information may
appear again. This semantic decision is model-based, not a guarantee that every
paraphrase is recognized. URLs and map links are resolved from supplied evidence,
not generated by the model. Source article bodies are not persisted. Date-only
sources are treated as day-level evidence, with deduplication across editions.

A failed or invalid generation preserves prior editions and publishes a failure
notice. Re-running a published edition does not call the API again, unless the manual
`replace_latest` editorial-correction option is explicitly selected. A correction
retains the reporting window and replaces the edition only after validation. The map and
briefing workflows share a write lock; Pages deploys on both workflow completions
because bot commits do not trigger an ordinary push workflow.

Run `python -m unittest test_briefing test_site test_selection test_coverage` with
feedparser, requests, openai, trafilatura and jsonschema installed. Tests cover DST,
late execution, evidence windows, repeated reports, material source revisions,
invalid citations, failure retention, duplicate runs and published asset boundaries.

## Missed-edition recovery

In addition to the 8 a.m./5 p.m. targets, an off-hour hourly check and successful
map refresh completion invoke the same catch-up path. This does not guarantee an
exact delivery time: GitHub may delay all scheduled work. The page now identifies
a missing expected edition after a 30-minute grace period, using New York calendar
time and daylight saving rules rather than a 26-hour age threshold. It refreshes
on reopening and every five minutes while open, retaining the loaded copy if a
refresh fails. Historical views still show the current publication warning.

Each automatic invocation generates at most one missing edition from the latest
two due slots, oldest first. Empty archives start with the latest due slot. A
newer published edition or opening brief covers earlier gaps; there is no unbounded
historical backfill. Delayed editions retain their scheduled date and kind, disclose
lateness, and use actual collection/publication times for their reporting window.
An already published slot does not fetch feeds or call the model again.

Automatic retries are limited to three attempts per slot, at least 45 minutes
apart. Failed generation keeps prior editions. A manual edition run can retry
an exhausted slot; editorial replacement remains an explicit manual option.
The attempts are recorded in `briefings.json`, trimmed after three days.
The existing shared writer lock now uses `queue: max` on both writers so retry
triggers cannot replace a queued map update or correction. Checkouts happen after
the serialized run starts and therefore read previously committed editions. A
failed push or infrastructure crash before the attempt record reaches GitHub can
still require manual recovery; this is not an exactly-once external API guarantee.

Tests require no API key or paid calls:

```
python -m unittest test_briefing test_site test_selection test_coverage
npm install --no-save --ignore-scripts jsdom@26.1.0
node --test test_briefing_ui.cjs test_briefing_dom.cjs
```
